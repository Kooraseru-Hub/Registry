# README badge assets

`sources.json` declares the static ShieldCN assets. `content/readme/images.json` supplies GitHub-only live overrides and the repository link base. Both README outputs use the same authored `content/docs/repository/README.md`, with target-specific image substitutions and benchmark layouts. DevForum badges use a common 24px display height. The renderer reads each generated PNG's IHDR dimensions and rounds its proportional width to the nearest pixel. Both HTML dimensions are emitted because DevForum does not reliably apply height alone. Widths are never authored or stored separately; the same PNG cache and upload references are retained.

The trusted publication job reads the last generated main branch using the existing Git fetch. It reuses a sanitized SVG only if the source URL and SHA-256 of the previously published bytes match the recorded values and those bytes pass the current sanitizer. Missing, changed, or invalid artwork is fetched again. Every publication rasterizes the current SVGs with the pinned renderer and hashes the resulting PNG files using Git blob IDs. The final PNG identity controls content reuse, while the configured public topic controls upload reuse. A changed source or renderer that produces identical PNG bytes needs no new upload if the existing public reference is still accessible. The banner is copied and hashed in exactly the same way. Subsequent identical publications need no ShieldCN requests or DevForum upload requests; public verification is read-only.

The generated `content/readme/devforum.json` on main contains upload references, source URLs, source SHA-256 digests, PNG paths and Git blob IDs, and measurement provenance. The original uploaded PNG bytes are retained under `content/images/devforum/` on main, including the banner, all eight badges and four charts. The next run compares the newly generated PNG blob ID with both the manifest and the actual PNG blob in the fetched main tree before reusing the corresponding upload. A missing or corrupted PNG invalidates that entry, so the first migration may upload every asset once. Old charts remain paired with their original metadata until a complete new measurement is supplied. CI publishes the manifest and README together. Before reusing an upload, the publisher reads the configured public topic and verifies the actual cooked public image URLs, including srcset variants. A missing, private, or inaccessible reference is replaced with a fresh upload. A manually replaced public reference is adopted only after comparing the original PNG bytes. Fresh uploads remain unconfirmed in the manifest until the public post contains them; do not attach them to a private test message. If the public topic has not yet been updated, a later publication may upload them again. Transient verification failures stop publication rather than cause mass reuploads. The publisher does not create or edit any forum post. An unchanged static source URL may change upstream; change the declared URL for an intentional artwork refresh.

## Credentials

Keep `DEVFORUM_USER_API_KEY` (secret) and `DEVFORUM_USER_API_CLIENT_ID` (variable) in the `ci-devforum` environment restricted to source. The generated CI controller resolves these names directly from that protected environment. CI-Engine does not declare any DevForum-specific credentials. Missing authentication fails publication rather than silently publishing the stale seed. Review and rehearsal jobs never upload. No forum posts are created or edited automatically.

Benchmark chart rasterization explicitly maps generic SVG font families to an installed sans-serif family (Liberation Sans, DejaVu Sans, Arial or Helvetica, in that order). Missing fonts or renderer diagnostics fail publication rather than silently dropping labels. Badge rasterization is unchanged. The PNG content hash remains the upload cache key; a different installed font may change chart bytes.
